# NWDP Boundary Guarded Importer Design

Status date: 2026-08-22

This design defines the future guarded importer for NWDP/GSI village-boundary staging rows.

It does not authorize running the importer yet.

## Import mode

The importer should support:

| Mode | DB writes | Purpose |
| --- | --- | --- |
| default dry run | no | validate what would be inserted/updated |
| `--apply` | yes | insert inactive staging rows after review |
| `--replace-batch` | guarded yes | supersede/rebuild same source batch only with explicit flag |
| `--limit` | no/yes | pilot subset for development |

Default must be dry-run.

## Guard requirements before `--apply`

The importer must refuse `--apply` unless all are true:

- migration tables exist;
- schema guard is healthy;
- candidate dry-run verifier is healthy;
- source batch metadata is supplied;
- source file checksum is supplied;
- source CRS/target CRS are supplied;
- candidate count matches expected source feature count;
- no unknown candidate buckets;
- no duplicate source feature indexes;
- no duplicate source keys;
- all rows will be inserted inactive;
- no runtime lookup table writes are planned.

## Target tables

The importer writes only to:

- `geography_boundary_import_batches`;
- `geography_boundary_source_features`;
- `geography_boundary_crosswalk_candidates`.

It must not write to:

- canonical `geography_states`;
- canonical `geography_districts`;
- canonical `geography_blocks`;
- canonical `geography_villages`;
- parcel tables;
- farmer tables;
- runtime lookup/promoted boundary tables.

## Import batch row

One batch row per source file/audit bundle.

Required values:

- `source_system = NWDP_GSI_VILLAGE_BOUNDARY`;
- `source_dataset = Village Boundary`;
- `source_producer_agency = Geological Survey of India`;
- `state_or_ut = Karnataka` for pilot;
- `source_format = SHP`;
- source resource/download URLs when known;
- source SHA-256;
- source file size;
- source CRS `WGS 84 / India NSF LCC`;
- source EPSG `7755`;
- target CRS `EPSG:4326`;
- manifest/geometry/crosswalk audit JSON summaries;
- `status = STAGED_DRY_RUN_VERIFIED` or `IMPORTED_INACTIVE`;
- `review_status = MANUAL_REVIEW`;
- `is_active = false`.

## Source feature row

One row per source feature.

Required values:

- source feature index;
- source codes: `stcode`, `dtcode`, `sdcode`, `bkcode`, `vlcode`;
- source names: state/district/subdistrict/block/village;
- source agency;
- source properties JSON if available;
- geometry hash if available;
- bbox/centroid audit values if available;
- feature category:
  - `VILLAGE_BOUNDARY`;
  - `REFERENCE_FEATURE`;
  - `SPECIAL_FEATURE`;
- geometry validation status;
- eligible for runtime after promotion: false;
- `is_active = false`.

## Crosswalk candidate row

One row per source feature.

Required values:

- source feature id;
- source feature index;
- candidate bucket;
- confidence;
- review status;
- proposed scope;
- proposed backend geography ids if available;
- proposed LGD codes if available;
- source codes JSON;
- source names JSON;
- match evidence JSON;
- promotion status `NOT_PROMOTED`;
- `is_active = false`.

## Idempotency

Default idempotency key:

    source_system + state_or_ut + source_format + source_file_sha256 + source_feature_index

Re-running the importer should report:

- existing batch count;
- existing source feature count;
- existing candidate count;
- would insert count;
- would update count;
- skipped duplicate count.

Without `--replace-batch`, existing rows must not be overwritten except safe metadata fill-ins that do not change reviewer decisions.

## Reviewer safety

Importer must never set:

- `review_status=APPROVED_FOR_PROMOTION`;
- `promotion_status=PROMOTED`;
- `is_active=true`.

Those belong to later review/promotion workflows only.

## Output report

Dry-run/apply report schema:

    nwdp_boundary_guarded_importer_report.v1

Required report fields:

- input candidate count;
- planned batch insert/update;
- planned source feature inserts;
- planned candidate inserts;
- skipped duplicates;
- unknown buckets;
- unsafe rows;
- rows planned inactive;
- rows effective in runtime;
- db writes attempted;
- apply mode;
- readiness flags.

## First implementation recommendation

Implement the importer in two steps:

1. `--dry-run` only script that reads candidate CSV and validates DB table existence.
2. Add `--apply` only after dry-run and table-existence checks are proven locally.

## Current decision

Do not implement DB writes yet.

Next implementation should be a dry-run importer skeleton that validates candidate CSV plus staging-table availability, and exits safely if migration 054 has not been applied.
