# NWDP boundary manual-review import plan

Status date: 2026-08-21

This document defines the conservative manual-review import plan for NWDP/GSI village-boundary crosswalk candidates.

Current status: design only. No database rows should be written until a separate guarded importer and verifier are implemented.

## Import principle

Mirror the CoRE/LGD import pattern:

1. Import only candidate rows, not active runtime mappings.
2. Preserve existing backend LGD geography as identity source of truth.
3. Keep every imported row ineffective until explicit review/promotion.
4. Keep source geometry and crosswalk candidates separate.
5. Keep unresolved village assignment manually gated.
6. Preserve audit history and source checksums.
7. Never let Android compute, repair, or promote boundary matches locally.

## Proposed importer behavior

A future importer should read a candidate CSV/JSON and stage rows with:

| Input bucket | Planned review status | Planned active status | Effective in runtime lookup |
| --- | --- | --- | --- |

| `DIRECT_VLCODE_PARENT_MISMATCH` | `MANUAL_REVIEW` | inactive | no |
| `PARENT_SCOPED_NAME_MATCH` | `MANUAL_REVIEW` | inactive | no |
| `PARENT_SCOPED_NAME_AMBIGUOUS` | `MANUAL_REVIEW` | inactive | no |
| `PARENT_MATCH_VILLAGE_UNRESOLVED` | `MANUAL_REVIEW` | inactive | no |

## Candidate import fields

A staged candidate row should retain:

- import batch id;
- source id;
- source resource URL;
- source file checksum;
- source feature index;
- source geometry checksum;
- source `stcode`;
- source `dtcode`;
- source `sdcode`;
- source `bkcode`;
- source `vlcode`;
- source district/subdistrict/block/village names;
- source agency;
- candidate bucket;
- confidence label;
- review status;
- proposed backend state id;
- proposed backend district id;
- proposed backend block id;
- proposed backend village id;
- proposed scope;
- reviewer decision;
- reviewer note;
- promotion status;
- created/updated timestamps.

## Geometry import fields

A separate geometry-feature row should retain:

- import batch id;
- source feature index;
- raw CRS;
- target CRS;
- geometry checksum;
- transformed geometry;
- transformed centroid or label point;
- geometry validation status;
- feature category;
- whether feature is eligible for runtime point-in-polygon after crosswalk promotion.

Geometry storage should not imply LGD assignment. Crosswalk promotion controls effective assignment.

## Verifier requirements

Before any import script can write rows, a dry-run verifier should prove:

- input file schema is recognized;
- candidate row count equals source feature count;
- candidate buckets sum correctly;
- all candidate rows carry source feature index and source codes;
- direct `vlcode` candidates have backend village ids;
- parent-mismatch candidates are not marked active;
- manual-review rows are inactive;
- special reference features are not assigned as villages;
- geometry CRS and target CRS are recorded;
- no duplicate active candidate would be created for the same source batch and feature index;
- no runtime lookup table changes are produced.

## Promotion requirements

Promotion must be a separate workflow.

Promotion should require:

1. candidate row exists and is inactive;
2. source batch is audited;
3. geometry plausibility is green;
4. CRS transform is verified;
5. source-to-backend crosswalk is reviewed;
6. candidate is not blocked;
7. reviewer identity and note are recorded;
8. prior active mapping is superseded only with audit history;
9. runtime consumers are explicitly enabled.

## Promotion buckets

Suggested promotion decisions:

| Promotion decision | Meaning |
| --- | --- |
| `PROMOTE_DIRECT_CODE_MATCH` | Direct `vlcode` match accepted after batch-level review. |
| `PROMOTE_REVIEWED_NAME_MATCH` | Manual reviewer accepted a scoped name match. |
| `PROMOTE_REFERENCE_ONLY` | Feature retained as district/subdistrict reference geometry, not village boundary. |
| `REJECT_SOURCE_MISMATCH` | Candidate rejected because source feature does not match backend geography. |
| `REJECT_SPECIAL_FEATURE` | River/reservoir/other special feature not eligible for village mapping. |
| `BLOCK_PENDING_SOURCE_REVIEW` | Source caveat unresolved. |

## Runtime boundaries

Until promotion exists:

- no Android UI change;
- no admin runtime boundary lookup;
- no parcel-village automatic assignment;
- no claim, subsidy, insurance, or fraud scoring;
- no point-in-polygon decisions.

After future promotion:

- runtime lookup may use promoted village boundaries only as reference geography;
- parcel geometry conflict rules still require manual review;
- cadastral truth and ownership remain out of scope;
- unresolved/non-promoted rows remain invisible to runtime matching.

## Current decision

Do not implement DB writes yet.

Next implementation should be a dry-run import planner/verifier that reads the candidate CSV and reports exactly what would be staged, excluded, blocked, and held for manual review.
